# tp137 联赛赛程与积分核算台

一个本地小工具：把参赛球队、比赛场地与整季赛程登记进来，打完的场次记上比分，页面立刻算出每个积分、净胜球与名次。左侧切视图，右侧抽屉里增删改，所有数字都来自本机的数据文件，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5137>

端口固定为 `5137`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

左侧导航共六个视图：

1. 概览：球队与场地数、赛程进度、已赛与待赛场次，下面列出最近五场赛果与积分榜前三
2. 球队：按参赛状态筛选、按队名或城市搜索；点新增或编辑打开右侧抽屉填写队名、简称、城市、主场、档位、分组、状态与备注
3. 场地：以卡片列出场地名称、城市、容量、可用日、主场球队与已排场次
4. 赛程：按轮次与状态筛选，逐场列出日期、时刻、对阵、比分、场地与状态；未打完的场次可以点登记比分，打完的场次会带上比分与胜者
5. 淘汰赛：按种子位抽签生成单败签表（2–16 队、非 2 的幂自动安排轮空），树状图上每场写明上一场是哪两场、胜者去哪一场的哪一边；点"←R1M2"之类的标签可跳到上一场，悬停球队行能看到它这条边一路追回首轮的种子位；登记比分后胜者自动落位到下一场对应边，横幅写明"下一场 R2M2 的右边换成谁"，打完决赛显示冠军
6. 积分榜：按名次列出场次、胜平负、进球失球、净胜与积分

任何一步不成立时，右上角弹出说明，并尽量把问题标到抽屉里对应的输入项上。

## 积分与排序口径

- 只统计状态为已赛的场次，延期、取消与待赛的场次不计入
- 积分按胜一场 3 分、平一场 1 分、负一场 0 分累加，规则记在数据文件的 `meta.points` 里
- 名次依次比较：积分高的在前 → 净胜球多的在前 → 进球多的在前 → 队名排序
- 净胜球等于进球数减失球数；积分榜随每次登记比分实时重算

## 登记口径

- 球队名称不重复、最长 24 个字；简称是两到四个大写字母且不重复；档位在 1 到 12 之间且不重复；分组为选填的一到四个字母或数字（用于淘汰赛同组首轮回避）；主场必须是已登记的场地；本赛季参赛球队最多 12 支
- 场地名称不重复、最长 30 个字；容量在 100 到 200000 之间；至少要选一个可用日，且同一天不能重复勾选
- 赛程的轮次在 1 到 40 之间，日期要真实存在，开赛时刻写成两位小时加两位分钟；主队与客队不能是同一支
- 同一轮里一支球队只能出场一次；同一天同一块场地两场比赛之间至少隔两小时（场地留空时按主队主场算）
- 比分只在状态为已赛时填写，取值是 0 到 99 的整数；状态不是已赛时填了比分会被拒绝
- 球队或场地被赛程引用时不能直接删除，页面会说明还有多少场挂着

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ meta, teams, venues, matches, knockout }`。落盘时先写临时文件再改名替换，写入过程中断不会把数据文件写坏；文件缺失或内容损坏时回落到初始数据。初始数据里八支球队、六个场地（其中三支球队共用中立体育场）、七轮单循环二十八场，前三轮已打完，第四轮有一场延期；另外带一张八队淘汰赛签表，首轮三场已打完（其中一场点球决胜、一场加时决胜），胜者已自动落到八强战。

## 淘汰赛口径

- 队数 2–16 支，档位必须正好排成 1、2、3……；不是 2 的幂时自动安排轮空，轮空按惯例留给最高档种子并自动晋级
- 签表按标准单败种子位生成：1、2 号种子只可能在决赛相遇，前四档半决赛后、前八档八强战后才可能相遇
- 抽签在不破坏种子分区的前提下搜索"同组球队首轮不相遇"的摆法（高种子分块 DFS + 低位种子匈牙利最优指派）；标准摆法无冲突时不走样，能避开就自动调位，避让不开时签表上方逐条写明是哪一组在哪一场相遇、为什么避不开
- 每场记录左右两边的来源（首轮种子位或上一场胜者）与去向（下一场的左边/右边），任意一场都能沿边往回追出它上游子树里全部的最初种子位
- 登记比分时上一场没打完（两边没到齐）不允许登记；常规时间打平不能按平局收场，必须选加时（填加时进球，加时仍平要求改踢点球）或点球决胜（填两边罚进数），总有一边晋级
- 胜者自动写到下一场对应边；改判一场会连锁作废它下游全部已赛场次并撤销冠军，避免下一场留着一支没赢出来的球队

## 接口一览

| 方法   | 路径                        | 说明                             |
| ------ | --------------------------- | -------------------------------- |
| GET    | /api/health                 | 服务状态检查                     |
| GET    | /api/summary                | 概览数字、最近赛果与积分榜前三   |
| GET    | /api/teams                  | 球队清单，支持状态筛选与关键词   |
| POST   | /api/teams                  | 新增球队                         |
| PATCH  | /api/teams/:id              | 修改球队                         |
| DELETE | /api/teams/:id              | 删除球队                         |
| GET    | /api/venues                 | 场地清单，支持关键词             |
| POST   | /api/venues                 | 新增场地                         |
| PATCH  | /api/venues/:id             | 修改场地                         |
| DELETE | /api/venues/:id             | 删除场地                         |
| GET    | /api/matches                | 赛程清单，支持轮次、状态与关键词 |
| POST   | /api/matches                | 新增赛程                         |
| PATCH  | /api/matches/:id            | 修改赛程                         |
| POST   | /api/matches/:id/result     | 登记比分，登记后自动标成已赛     |
| DELETE | /api/matches/:id            | 删除赛程                         |
| GET    | /api/knockout               | 查看当前淘汰赛签表（无签表 404） |
| POST   | /api/knockout/generate      | 按勾选球队与档位抽签             |
| POST   | /api/knockout/matches/:id/result | 登记淘汰赛场次比分，胜者自动晋级 |
| DELETE | /api/knockout               | 清空当前签表                     |
| GET    | /api/standings              | 积分表，支持关键词               |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
